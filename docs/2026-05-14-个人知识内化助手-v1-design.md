# 个人知识内化助手 V1 设计稿

日期：2026-05-14
版本：V1（M0）

## 1. 产品定位与差异化北极星

一句话定位：
一个帮用户把碎片收藏转化为个人能力的知识内化 Agent。

V1 北极星原则：
1. 先收进来，后变清楚（可选意图批注）
2. 内化优先，不做摘要工具
3. 每条内容有去向
4. 每天只给最值得做的一小步
5. 为调用而沉淀，不为存储而沉淀

非目标（V1 不做）：
- 不做大而全编辑器/数据库/插件生态竞争
- 不做复杂多层生命周期展示给用户
- 不做复杂跨主题深推理编排

## 2. 首发用户与首发场景

首发用户：
收藏很多、想成长、但缺乏稳定知识管理习惯的个人学习者/知识工作者。

首发场景：
学习成长（兼容少量工作输出），并重点覆盖“当下觉得有价值但没时间处理，先留到后面却容易越积越多”的临时兴趣内容场景。

## 3. MVP 差异化闭环（7 步）

1. 用户收录内容（可选填写意图批注）
2. 用户必选：稍后看 / 收藏
3. Agent 判断状态并入队
4. Agent 生成内化笔记草稿
5. Agent 归入主题并关联 1-3 条旧记录
6. Agent 给出今日知识任务
7. 用户可自然语言按场景调用

## 4. 输入层设计（V1）

支持 4 类输入：
1. 文字
2. 链接（按类型读取；视频链接采用分级读取策略）
3. 截图/图片（OCR）
4. 本地文档（PDF/Markdown/Word 等）

不支持（V1）：
- 语音转文字

视频链接读取策略（V1）：
1. 先保存链接和基础信息
2. 能拿字幕就拿字幕
3. 没字幕就提示用户：是否转写音频
4. 只有在必要时才分析画面

解析失败策略：
- 不走补录流程
- 直接反馈：读取失败 + 失败原因（如权限限制/反爬限制/内容删除/格式不支持）
- 记录保留并打“读取失败”异常标记

## 5. 收录与状态机设计（简化）

收录规则：
- 意图批注：完全可选
- 每次收录必选：稍后看 / 收藏

入口映射：
- 稍后看 -> 暂存
- 收藏 -> 待内化

用户可见主状态（仅 3 个）：
1. 暂存
2. 待内化
3. 已沉淀

系统动作：
- 删除
- 归档

说明：
- 读取失败是异常标记，不属于主生命周期状态
- 状态是系统管理机制，前台以“下一步动作建议”为主

## 6. 内化笔记模板（V1）

每条内化笔记 7 个字段：
1. 标题（优先使用来源标题；无标题时自动总结生成）
2. 来源（链接/截图/文档/文本）
3. 核心观点（AI 提炼）
4. 我的理解（用户可补，默认可空）
5. 可复用场景（AI 给 1-3 个）
6. 关联旧记录（1-3 条）
7. 下一步建议（回顾/补充/归档）

## 7. 知识结构与连接（V1）

知识结构层级：
- 两层：主题 -> 子主题

归属规则：
- 单条记录最多归入 1 个子主题

连接策略：
- 每条待内化/已沉淀记录关联 1-3 条历史记录

## 8. 回顾与提醒机制

每日任务：
- 固定 3 条

提醒文案结构：
1. 今日概览：今日待暂存数、待内化数、已内化数
2. 今日建议处理（最多 3 条）：每条包含“为什么今天处理 + 建议动作”

节奏机制：
- 每日轻任务
- 每周清理盘点
- 每月重整盘点

积压熔断：
- 暂存（稍后看）超过 80 条 -> 进入减负模式
- 减负模式：每天仅推最高价值任务 + 一键清理建议

行为熔断：
- 连续 7 天未处理今日任务 -> 自动进入减负模式

## 9. 场景化调用与问答（V1）

V1 支持 4 类问答：
1. 按主题
2. 按场景
3. 按历史
4. 检索定位

回答信任机制（必做）：
- 无论用户问什么，都附“参考记录列表”（标题 + 来源 + 时间）

后续迭代储备（非 V1）：
- 对比归纳
- 观点生成
- 输出辅助
- 决策支持
- 空白发现

## 10. 成长反馈（V1）

频率：
- 每周一次

周反馈最小指标集：
1. 本周新增记录数
2. 本周已沉淀数
3. 关注主题 Top3
4. 可复用笔记数
5. 下周建议补强 1 个主题

## 11. 体验原则与防失败机制

体验原则：
- 低门槛输入
- 少打扰
- 以建议动作替代复杂状态心智

防失败机制：
- 积压熔断阈值：80 条
- 连续 7 天未处理任务触发减负模式

## 12. 版本切分与验收

M0（V1）验收标准：
1. 7 步闭环全跑通
2. 每日任务稳定产出 3 条
3. 问答可返回答案并附参考记录列表

---

## 附：当前达成的关键共识

- 不做“另一个 Notion/Obsidian”，而做“知识内化助手”
- 生命周期从复杂多状态收敛到 3 个用户可见状态
- 用任务驱动体验，避免用户维护系统
- 用证据化回答建立信任
- 优先保证闭环可持续，而非功能堆叠
