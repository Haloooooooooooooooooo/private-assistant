# 个人知识内化助手 V1 PRD

日期：2026-05-15
状态：待评审
范围：电脑端 Web 主工作台 V1

## 1. 产品概述

个人知识内化助手是一个面向个人学习、研究和内容消化的 AI Agent 产品。它帮助用户低摩擦收录资料，将原始内容自动转化为结构化笔记，并归入个人知识结构；之后用户可以基于自己的知识库进行证据化问答，并将有价值的回答回写到笔记中，形成持续沉淀。

V1 的产品重点不是做一个通用聊天机器人，也不是做一个传统收藏夹，而是跑通“收录后处理”的最小可用闭环。

核心闭环：

```text
收录资料
→ 解析内容
→ AI 内化为结构化笔记
→ 归入主题/子主题
→ 图谱化展示
→ 基于知识库问答
→ 回写有价值回答
→ 今日提醒/周反馈推动继续处理
```

## 2. 目标用户与使用场景

### 2.1 目标用户

V1 面向个人知识工作者和学习型用户，包括：

- 经常阅读文章、报告、论文、课程资料的人。
- 经常收藏资料但后续很少整理的人。
- 希望把资料转化成可复用观点、结论和问题库的人。
- 希望 AI 回答能基于自己资料，并附带来源的人。

### 2.2 核心场景

场景 1：快速收录资料

用户看到一段文本、链接、截图或文档，希望先低摩擦保存下来，不被复杂整理流程打断。

场景 2：稍后处理资料

用户希望系统提醒自己处理未读、未内化资料，而不是让内容沉在收藏夹里。

场景 3：把资料内化成笔记

用户不只是想要摘要，而是希望 AI 生成包含观点、概念、个人理解、可复用结论、使用场景、相关问题和原文依据的结构化笔记。

场景 4：浏览知识结构

用户希望看到自己的知识沉淀不是散乱列表，而是主题、子主题和笔记构成的图谱。

场景 5：基于知识库问答

用户向 AI 助手提问，希望回答来自自己的知识库，并且能看到引用来源。

场景 6：把问答继续沉淀

用户觉得某次问答有价值，希望一键加入相关笔记，成为未来可检索的知识。

## 3. 产品目标与成功标准

### 3.1 V1 目标

- 让用户能快速收录文本、链接、图片和常见文档。
- 让用户能把原始记录一键内化成结构化笔记。
- 让已沉淀笔记能进入主题/子主题结构。
- 让用户能通过知识图谱查看沉淀成果。
- 让 AI 助手能基于知识库回答问题并附来源。
- 让有价值回答能回写到笔记。
- 让今日提醒和周反馈推动用户持续处理资料。

### 3.2 成功标准

- 用户能在 30 秒内完成一条资料收录。
- 用户能从收录记录生成一条可编辑的 7 字段内化草稿。
- 用户确认后，记录能进入已沉淀状态，并生成对应笔记。
- 知识库图谱能展示主题、子主题、笔记的结构关系。
- AI 助手回答必须展示至少一条来源；证据不足时明确说明不确定。
- 用户能将 AI 回答回写到指定笔记。
- 日历能区分有记录/无记录日期，并展示今日提醒或周反馈。

## 5. 状态与术语

### 5.1 用户可见状态

```text
稍后看
待内化
已沉淀
```

状态说明：

- 稍后看：用户先保存，暂不处理。
- 待内化：用户明确希望后续转化为结构化笔记。
- 已沉淀：记录已生成结构化笔记，并进入知识库。

### 5.2 标签与主题

- 标签是轻量标记，可多选，可重命名。
- 主题是知识结构归属。
- 单条笔记最多归属 1 个子主题。
- V1 主题层级固定为两层：主题 -> 子主题。

### 5.3 搜索结果状态

搜索时展示前端临时 `搜索结果` chip，用于提示当前处于搜索态。该 chip 不写入真实标签系统。


局部功能：

```text
1. 详情抽屉
2. 内化草稿抽屉
```

## 7. 页面需求

### 7.1 收录箱

定位：V1 主工作页，用于快速收录、筛选、处理和内化记录。

页面结构：

- 顶部信息 icon
- 快速添加栏
- 搜索与筛选区
- 记录列表
- 详情抽屉
- 内化草稿抽屉

快速添加栏字段：

- 内容输入：支持文本、链接、粘贴图片。
- 批注输入：我的理解，选填。
- 状态选择：稍后看 / 待内化。
- 附件入口：选择或拖拽文件。
- 添加按钮：支持回车提交。

筛选能力：

- 一级状态：全部 / 稍后看 / 待内化 / 已沉淀。
- 二级筛选：来源、时间、标签。
- 标签支持新增、重命名、删除、多选。

搜索能力：

- 搜索框与记录列表在同一区域。
- 支持实时下拉联想。
- 搜索结果直接显示在主体列表。
- 搜索态显示临时 `搜索结果` chip。
- 点击 chip 上的关闭按钮退出搜索态。

记录列表字段：

- 标题
- 来源
- 收录时间
- 状态
- 标签
- 异常标记

记录动作：

- 稍后看：转待内化、一键内化、删除。
- 待内化：一键内化、删除。
- 已沉淀：查看笔记、在知识库定位、删除。

验收标准：

- 用户能添加一条文本记录，并立即在列表看到。
- 用户能用状态和标签筛选记录。
- 用户搜索后能看到结果列表和临时搜索 chip。
- 用户能打开详情抽屉并修改批注、标签和状态。
- 用户能触发一键内化并打开内化草稿抽屉。

### 7.2 详情抽屉

定位：查看和轻编辑原始记录。

展示内容：

- 原始内容
- 来源信息
- 收录时间
- 当前状态
- 标签
- 我的理解
- 附件信息
- 解析状态
- 异常原因

可操作项：

- 编辑我的理解
- 编辑标签
- 修改状态
- 查看原文
- 触发一键内化
- 删除记录

验收标准：

- 任意记录都能打开详情抽屉。
- 用户修改批注、标签、状态后能保存。
- 解析失败记录能展示失败原因。
- 一键内化入口在详情抽屉中可用。

### 7.3 内化草稿抽屉

定位：承载一键内化后的轻确认流程。

触发方式：

- 收录箱列表点击一键内化。
- 详情抽屉点击一键内化。

7 字段结构：

```text
核心观点
关键概念
我的理解
可复用结论
使用场景
相关问题
原文依据
```

用户操作：

- 查看 AI 生成草稿。
- 编辑任一字段。
- 保存为笔记。
- 取消或返回。

保存后结果：

- 原记录进入已沉淀状态。
- 生成结构化笔记。
- 触发主题/子主题归类。
- 生成检索分块。
- 知识图谱可展示该笔记。

验收标准：

- 一键内化后能看到完整 7 字段草稿。
- 用户能编辑草稿并保存。
- 保存后记录状态变为已沉淀。
- 保存后的笔记能在知识库中查看。

### 7.4 知识库

定位：展示用户已沉淀知识的结构成果。

页面结构：

- 主区域：知识图谱
- 右侧：笔记详情抽屉

图谱节点：

- 主题节点
- 子主题节点
- 笔记节点

图谱边：

- V1 以结构边为主：主题 -> 子主题 -> 笔记。
- 语义边和复杂关系展示放后续增强。

图谱能力：

- 缩放
- 拖拽
- 节点点击
- 选中高亮
- 搜索定位
- 从收录箱跳转定位目标笔记
- 不同主题使用不同颜色

主题管理：

- V1 不提供手动新建复杂主题体系入口。
- 用户可重命名主题/子主题。
- AI 可以生成主题归类、新建、合并、拆分建议。
- 合并/拆分建议不自动执行，需用户确认。

验收标准：

- 已沉淀笔记能在图谱中出现。
- 点击笔记节点能打开右侧详情抽屉。
- 从收录箱点击“在知识库定位”能跳转并高亮目标笔记。
- 图谱节点和主题颜色能清晰区分。

### 7.5 AI 助手

定位：独立知识问答模块，只基于用户知识库回答。

核心规则：

- 不做通用闲聊。
- 默认保留多轮会话记忆。
- 每条回答必须附参考记录。
- 证据不足时明确说明不确定。

页面能力：

- 输入问题。
- 展示多轮问答。
- 展示来源记录。
- 支持继续追问。
- 支持将回答加入笔记。

来源信息至少包含：

- 标题
- 来源
- 时间

验收标准：

- 用户能基于知识库提问并获得回答。
- 回答能显示来源记录。
- 无充分依据时不强行回答。
- 用户能点击“加入笔记”触发回写。

### 7.6 笔记追问抽屉

定位：从具体笔记出发进行上下文追问。

触发方式：

- 笔记详情中点击 `基于此笔记提问`。

能力：

- 自动挂载当前笔记上下文。
- 优先基于当前笔记回答。
- 可召回相关笔记作为补充证据。
- 回答仍需附来源。
- 支持回写到当前笔记。

验收标准：

- 从笔记详情能打开追问抽屉。
- 提问时自动带入当前笔记上下文。
- 回答可以回写到当前笔记。

### 7.7 日历提醒弹窗

定位：通过今日提醒和周反馈推动用户持续处理资料。

入口：

- 顶部信息 icon。

日历能力：

- 有记录日期和无记录日期使用不同颜色。
- 点击日期打开当日信息弹窗。
- 当日同时存在今日提醒和周反馈时，同层展示两张卡。

今日提醒：

- 默认每天 22:00 生成一次。
- 候选范围：稍后看、待内化中的未完成记录。
- 固定最多 3 条，不足 3 条则按实际返回。
- 每条包含建议处理理由和建议动作。

周反馈：

- 默认每周一 09:00 生成一次。
- 统计上一个自然周。
- 包含本周新增记录数、本周已沉淀数、关注主题 Top3、可复用笔记数、下周建议补强主题。

有记录日期判定：

- 新增收录。
- 状态变更。
- 完成内化。
- AI 助手回写笔记。

验收标准：

- 用户能通过信息 icon 打开日历。
- 日期能区分有记录/无记录。
- 用户能查看某日提醒卡片。
- 今日提醒和周反馈按快照保存。

## 8. 附件与解析规则

V1 支持：

- pdf
- docx
- md
- txt
- png
- jpg
- jpeg
- webp

V1 暂不支持：

- xls
- ppt
- zip

处理规则：

- 前端使用统一附件入口。
- 图片走 OCR。
- 文档按扩展名走对应解析器。
- 不支持文件仍保留记录，并标记不支持原因。
- 每个附件生成独立记录。
- 附件以 chip 展示并支持移除。

验收标准：

- 用户能上传支持格式附件。
- 不支持格式能展示明确原因。
- 附件记录能在收录箱列表中出现。

## 9. AI 与 Agent 规则

V1 不把所有环节都包装成 Agent。确定性任务走 Workflow，需要语义理解和生成的环节才使用 Agent。

工作流与 Agent：

```text
收录解析 Workflow
内化 Agent
知识结构 Agent
证据化问答 Agent
回写沉淀 Workflow
提醒反馈 Workflow
```

AI 输出规则：

- 内化必须基于原文和用户批注。
- 问答必须基于知识库证据。
- 回答必须附来源。
- 证据不足时说明不确定。
- 不自动执行高风险结构变更。
- 主题合并/拆分只生成建议，由用户确认。

## 10. 非功能需求

体验要求：

- 页面第一眼应完整、清爽、好用。
- 重要操作应有明确状态反馈。
- 抽屉、弹窗和列表不应互相遮挡。
- 搜索、筛选、查看详情应流畅。
- 图谱需要优先保证可读性，而不是复杂关系密度。

可靠性要求：

- AI 或解析失败不能导致记录丢失。
- 失败原因需要可见。
- 重要任务需要保留执行日志。
- 历史提醒和周反馈按快照保存，默认不自动重算。

性能要求：

- V1 图谱不一次性加载无限量节点。
- 大文件不直接写入数据库，文件本体放 Storage。
- AI 问答不全库塞入模型，必须先检索再回答。
