## 0. 已确认 UI 布局（2026-05-15）

本次评审已确认采用 **A 方案：左侧窄导航 + 顶部工具栏 + 主区工作台 + 右侧详情抽屉**。

固定布局规则：

- 左侧窄导航固定宽度（建议 64-72px），仅承载三大模块入口：收录箱、知识库、AI 助手。
- 顶部工具栏全局固定，右侧常驻信息 icon 与日历/提醒入口。
- 主工作区随模块切换，不切换全局壳层。
- 详情与次级任务一律走右侧抽屉（记录详情、内化草稿、笔记追问），避免主区过载。
- 知识库模块保持“图谱主画布 + 右侧详情”的双栏工作形态，但仍在同一 App Shell 内切换。

页面信息层级：

- 一级：快速添加、主筛选、主列表/主图谱（始终在主区可见）。
- 二级：详情内容、编辑项、来源与关联信息（进入右侧抽屉）。
- 三级：提醒、反馈、补充信息（popover/dialog 内展示）。

交互原则：

- 优先保证“收录 -> 搜索/筛选 -> 详情 -> 一键内化 -> 沉淀入库 -> 图谱查看 -> 追问”的主路径连续。
- 所有跨模块跳转保持上下文（可定位到目标记录/笔记），不重置用户视角。
- 不引入营销化大 Hero 与装饰性首屏，保持知识工作台风格。

## 1. 目标

本阶段目标是先做出一个看起来完整、清爽、好用的电脑端 Web 主工作台，让用户能看到产品的核心形态和主流程。

本阶段只覆盖：

- P0：项目初始化与基础技术栈
- P1：高保真 UI 骨架

本阶段暂不接：

- Supabase 真实数据
- FastAPI 后端
- 真实 Agent 调用
- 真实 RAG 检索
- 真实文件解析
- 登录鉴权

所有页面使用 mock 数据，但组件结构、字段命名、状态设计要贴近后续真实数据模型，避免 P2 接 Supabase 时大改。

## 7. P1 任务拆分

### P1.1 App Shell 与主导航

任务：

- 实现电脑端主布局。
- 左侧或顶部导航包含：收录箱、知识库、AI 助手。
- 顶部保留信息 icon。
- 主区域根据导航切换页面。

建议：

- SaaS/知识工作台风格，避免营销页和大 hero。
- 信息密度适中，突出可操作性。

验收：

- 用户能在三大模块之间切换。
- 信息 icon 始终可见。
- 桌面端布局稳定，不出现明显重叠。

### P1.2 收录箱页面布局

任务：

- 实现快速添加栏。
- 实现搜索框。
- 实现状态一级筛选。
- 实现来源、时间、标签二级筛选。
- 实现记录列表。
- 实现列表动作按钮。

快速添加栏字段：

- 内容输入
- 我的理解
- 状态选择
- 附件入口
- 添加按钮

验收：

- 快速添加栏视觉上是第一操作入口。
- 搜索和记录列表在同一主体区域。
- 列表字段包含标题、来源、时间、状态、标签、操作入口。
- 异常记录不单独占一列，而是在标题后显示异常提示 icon，hover 可查看报错原因。
- 三种状态的记录有清楚区分。

### P1.3 收录箱基础交互

任务：

- 实现本地 mock 添加记录。
- 实现状态筛选。
- 实现标签筛选。
- 实现搜索过滤。
- 搜索时显示临时 `搜索结果` chip。
- 点击 chip 的关闭按钮退出搜索态。
- 点击记录打开详情抽屉。
- 为每条记录提供固定的 `查看原笔记` 操作入口。

验收：

- 添加记录后能立即出现在列表。
- 搜索不会写入真实 tag。
- 筛选和搜索可以组合工作。
- 详情抽屉能正确显示当前记录。
- `查看原笔记` 在三种状态记录上都可用。

### P1.4 记录详情抽屉

任务：

- 展示记录标题、来源、时间、状态、标签、摘要。
- 展示我的理解。
- 展示附件 chip。
- 附件区域提供追加上传入口。
- 展示解析状态和异常原因。
- 提供编辑状态、标签、我的理解的 UI。
- 提供 `查看原笔记` 入口。
- 提供一键内化入口。
- 已沉淀记录额外提供 `AI笔记` 和知识库定位入口。

验收：

- 正常记录和异常记录都能被展示。
- 异常原因可见。
- 一键内化按钮在稍后看和待内化记录上可用。
- 待内化记录不提供 `转稍后` 操作。
- 三种状态记录都提供 `查看原笔记` 入口。
- 纯文本记录点击 `查看原笔记` 时打开全文弹窗，而不是外链跳转。
- 已沉淀记录展示 `AI笔记` 和知识库定位入口。

### P1.5 内化草稿抽屉

任务：

- 点击一键内化后打开草稿抽屉。
- 使用 mock 生成 7 字段草稿。
- 7 字段可编辑。
- 提供保存、取消按钮。
- 保存后模拟将 record 状态改为已沉淀。

7 字段：

- 核心观点
- 关键概念
- 我的理解
- 可复用结论
- 使用场景
- 相关问题
- 原文依据

验收：

- 用户能完整看到 7 字段。
- 字段排版不拥挤。
- 保存后列表状态能更新。
- 保存后能提示已沉淀。
- 已沉淀后的 `AI笔记` 默认以文章式内容展示，而不是 7 字段逐条平铺。

### P1.6 知识库图谱页面

任务：

- 实现两栏布局：主图谱 + 右侧详情抽屉。
- 使用 React Flow 渲染主题、子主题、笔记节点。
- 实现结构边：主题 -> 子主题 -> 笔记。
- 不同主题使用不同颜色。
- 支持节点点击、选中高亮。
- 支持从收录箱模拟跳转定位目标笔记。

验收：

- 图谱第一眼能表达“知识结构”。
- 节点层级清晰。
- 点击笔记节点能打开右侧详情。
- 图谱不需要复杂语义边，但视觉上要完整。

### P1.7 图谱右侧笔记详情抽屉

任务：

- 展示笔记标题。
- 展示所属主题/子主题。
- 展示文章式 `AI笔记` 内容。
- 展示来源记录。
- 展示相关笔记 mock。
- 提供 `基于此笔记提问` 按钮。

验收：

- 用户能从图谱节点进入笔记详情。
- `AI笔记` 内容自然、可读，不呈现机械表单感。
- 追问入口清晰。

### P1.8 AI 助手页面

任务：

- 实现对话页面布局。
- 展示 mock 多轮消息。
- 用户输入框。
- 回答卡片展示来源记录。
- 展示证据不足的回答样式。
- 提供 `加入笔记` 按钮。

验收：

- 页面明确不是通用聊天，而是知识库问答。
- 每条 mock 回答能看到来源区域。
- 加入笔记按钮清晰。

### P1.9 笔记追问抽屉

任务：

- 从笔记详情点击 `基于此笔记提问` 打开追问抽屉。
- 抽屉顶部显示当前挂载笔记。
- 展示基于当前笔记的 mock 问答。
- 支持 mock 回写按钮。

验收：

- 用户能理解当前问题基于哪条笔记。
- 追问抽屉和 AI 助手主页面体验一致但范围更聚焦。

### P1.10 信息 icon、日历与提醒弹窗

任务：

- 顶部信息 icon 打开日历 popover/dialog。
- 日历区分有记录/无记录日期。
- 点击日期展示当日信息。
- 展示今日提醒卡。
- 展示周反馈卡。
- 当日同时存在两类卡片时同层展示。

验收：

- 用户能看到哪些日期有记录。
- 今日提醒最多展示 3 条建议。
- 周反馈展示核心指标。
- 弹窗不会遮挡关键操作区域到不可用。

### P1.11 视觉打磨与响应约束

任务：

- 统一颜色、间距、圆角、阴影、字体层级。
- 检查按钮文字不溢出。
- 检查抽屉宽度、列表行高、图谱节点大小。
- 检查常见桌面宽度下布局稳定。
- 补齐空状态和加载状态 mock。

验收：

- 页面不显得像临时 demo。
- 主要文字不重叠、不溢出。
- 空状态、异常状态、正常状态都能展示。
- 视觉风格适合知识工作台，而不是营销落地页。

## 11. 风险与控制

风险 1：UI 骨架做得太静态，后面接数据重写。

控制：

- P1 就先定义接近真实的数据类型。
- mock 数据结构模仿后续 Supabase 表。
- 组件按业务边界拆分，不把逻辑全部写在页面文件里。

风险 2：图谱花费过多时间。

控制：

- V1 图谱只做结构边。
- React Flow 先使用 mock 布局。
- 不做复杂自动布局和语义边。

风险 3：第一版视觉像后台管理系统，缺少产品记忆点。

控制：

- 图谱页面作为视觉亮点。
- 收录箱保持高效工作台风格。
- 内化草稿抽屉突出 7 字段价值。

风险 4：页面太满。

控制：

- 使用抽屉承载详情。
- 主页面只展示当前最重要操作。
- 次级信息放入详情区域或 hover/popover。
